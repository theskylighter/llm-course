**Retrieval-augmented generation fetches relevant passages from an external index and puts them in the prompt, turning a memory problem into a reading problem.** Knowledge lives in an index you can update in minutes, and answers can cite their source.

## The Problem: The Model Does Not Know What Changed

Ask a model "who is the prime minister of Japan right now?" Follow the ladder.

**Attempt 1: make the model know more.** Train bigger, longer. But presidents, ministers, CEOs and champion teams keep changing, and retraining is costly. Facts go stale the day training stops. Knowledge for **less popular ("torso" and tail) entities and lower-resource languages** is thin (lecture 26).
**Attempt 2: paste everything into the prompt.** The context window is finite, attention cost grows with length (Chapter 4), and models use long inputs unevenly. Put in only the *relevant* part.
**Attempt 3: fetch the relevant part first.** That is RAG.

> [!compiler] Three failure modes of a closed-book model
> **Stale:** the answer was true at training time. **Missing:** the fact was rare in the corpus. **Unverifiable:** the model gives no source, so a hallucination looks identical to a correct answer. RAG attacks all three by turning a *memory* problem into a *reading* problem.

## The Pipeline: Index, Retrieve, Generate

> [!compiler] Stage 1: indexing (offline)
> Split documents into **chunks**, embed each chunk with an encoder, store the vectors in an index. **Chunk size and overlap:** too small and a chunk loses context, too large and the embedding blurs several topics. Example: a 10,000-token document, chunks of 500 tokens, overlap 50, so stride 450 and $\lceil(10000-500)/450\rceil+1=23$ chunks.

> [!compiler] Stage 2: retrieval
> **Sparse (lexical):** TF-IDF or **BM25** over an inverted index. Strong when the query shares exact words with the answer, blind to paraphrase. **Dense:** a **bi-encoder** embeds query and passage separately, and relevance is an inner product $s(q,p)=E_Q(q)^{\top}E_P(p)$. Dense Passage Retrieval (DPR) trains this contrastively with in-batch negatives. A practical default is **hybrid**: run BM25 and dense search, merge (for example by reciprocal rank fusion), then re-rank. **HyDE** asks the LLM to write a *hypothetical answer* and embeds that instead of the query.

> [!compiler] Stage 3: generation
> Put the retrieved passages in the prompt and ask the model to answer *from them*. The two instructions that matter most are "use only the sources" and "say so if absent": without them the model blends retrieved text with its parametric memory.

:::analogy
An open-book exam. The student does not need to memorise the whole library; they need to know how to find the right page and how to answer from it.
:::

```python
import math

def n_chunks(doc_len, size, overlap):
    stride = size - overlap
    return math.ceil((doc_len - size) / stride) + 1

print("chunks:", n_chunks(10000, 500, 50))

docs = {
    "d1": "monsoon rains arrived in delhi early this year",
    "d2": "the prime minister of japan changed after the election",
    "d3": "delhi traffic rules changed this year",
}
def score(query, text):                  # a tiny lexical score: word overlap
    return len(set(query.split()) & set(text.split()))

query = "who is the prime minister of japan"
ranked = sorted(docs, key=lambda d: -score(query, docs[d]))
print("ranking:", ranked)

def rrf(rankings, k=60):                 # reciprocal rank fusion of several rankings
    out = {}
    for r in rankings:
        for pos, d in enumerate(r):
            out[d] = out.get(d, 0) + 1 / (k + pos + 1)
    return sorted(out, key=lambda d: -out[d])
print("fused:", rrf([["d2", "d1", "d3"], ["d2", "d3", "d1"]]))
```

```output
chunks: 23
ranking: ['d2', 'd1', 'd3']
fused: ['d2', 'd1', 'd3']
```

> [!compiler] The original RAG model, as a probability (Lewis et al. 2020)
> A latent passage $z$ is marginalized over the top-$k$ retrieved. **RAG-Sequence** uses one passage for the whole answer; **RAG-Token** lets each output token choose its own passage:
> $$p(y\mid x)\approx\prod_{i=1}^{N}\sum_{z\in\text{top-}k}p_\eta(z\mid x)\,p_\theta(y_i\mid x,z,y_{<i})\qquad\text{(RAG-Token)}$$
> Here $p_\eta(z\mid x)\propto\exp(E_P(z)^{\top}E_Q(x))$ is the retriever and $p_\theta$ the generator (BART in the paper).

## Where Retrieval Enters the Model, and How to Evaluate It

| Method | Where retrieved text enters | Note |
|---|---|---|
| **In-context RALM / REPLUG** | prepended to the prompt of a *frozen* model | works with API-only models |
| **kNN-LM** | output: interpolate the LM distribution with one from nearest neighbours | no retraining; large datastore |
| **REALM** | retriever trained **during pre-training** with masked LM | retrieval is learned |
| **RETRO** | chunked **cross-attention** to retrieved neighbours | tiny models match much larger ones |

> [!compiler] Evaluating RAG: RAGAs (from memory of Es et al. 2023)
> A wrong answer may come from the *retriever* or the *generator*, so evaluate the parts. **Faithfulness** $=\dfrac{\#\text{claims supported by the context}}{\#\text{claims in the answer}}$ (3 of 4 supported gives 0.75). **Answer relevance**, **context relevance / precision**, and **context recall**. For the retriever alone: **recall@k**, **MRR**, **nDCG**.

:::def
**Retrieval-augmented generation (RAG)** conditions a language model's output on passages retrieved from an external corpus (by sparse, dense or hybrid search), so that knowledge can be updated by changing the index rather than the weights.
:::

:::key
- Closed-book LLMs are stale, incomplete and unverifiable; RAG moves knowledge to an updatable index.
- Pipeline: chunk and embed, retrieve (BM25, bi-encoder, re-rank), generate from the passages.
- Retrieval and generation fail independently, so measure faithfulness, relevance and recall@k.
:::

:::mistakes
- "RAG fine-tunes the model on new facts." The index changes, the weights do not.
- "Dense retrieval always beats BM25." Not on exact names or rare terms; hybrid is safe.
- "More retrieved passages is better." Irrelevant context distracts and costs tokens.
- "RAG removes hallucination." It reduces it; faithfulness errors remain.
:::

:::exam
- *Chunk count:* document length, chunk size, overlap.
- *"Why can RAG answers still be wrong?"* Retriever miss, generator ignores or misreads context.
:::
